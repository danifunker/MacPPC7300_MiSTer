# Power Macintosh 7300 ROM (077D.34F2), annotated disassembly

The 4 MB ROM of the user's Power Macintosh 7300 (`ppctest/runs/my7300.rom`:
68k header machine 07, version 7D, release 34F2, header checksum `960E4BE9`,
CRC32 `7910CDF9`; the "7300/7600/8600/9600" ROM, Open Firmware 1.0.5), the
reference ROM since 2026-10-07. Taken apart exactly as `rom7600/` takes apart
the 7600's ROM (077D.28F2): the method, the listing format and the notes for
an implementation are in `rom7600/README.md` and hold here. Committed since
2026-10-08 (the user's request); the ROM image itself is not.

Generated by `tools/` (a copy of `rom7600/tools/` with titles changed, the
coverage run made as dingusppc's `pm7300`, and the summary's phase counts
this ROM's), plus `tools/remap_annotations.py`, which moves the 7600 ROM's
hand-written notes to this ROM's addresses. Regenerate from WSL:

    bash tools/regen.sh                 # build, coverage run (cov7300), all outputs
    SKIP_COV=1 bash tools/regen.sh      # reuse ~/.cache/ppcmac/romdisasm/cov7300

## What differs from the 7600's ROM (28F2)

| ROM offset | region | bytes that differ | |
|---|---|---|---|
| 000000-0D34FF | 68k code | 13 | in place: every 68k address is the same |
| 0D3500-0D4CFF | trap tables | 0 | |
| 0D4D00-2FFFFF | resources | most, by a shift | the same 180 resources in the same order; from `DRVR` 48 (16 bytes longer) on, everything sits 16 bytes later, then `libi` -20004 moved; changed in length: `DRVR` 48, `nitt` 43 (the native SCSI Manager 4.3, 0x170 bytes longer), and `ndrv` 505 moved. The startup chime (`beep` 0, FFE00010) and the error beep (`beep` 1, FFE40010) are where they were |
| 300000-30BFFF | PowerPC start-up code | 6,969 | changed code; from about FFF03090 on it sits 0x60 to 0x1DC bytes later |
| 30D000-30DFFF | ConfigInfo | 34 | |
| 310000-31FFFF | NanoKernel | 3,069 | 15,521 of its 16,384 words where they were |
| 320000-32FFFF | HWInit | 137 | the same code, mostly moved |
| 330000-34FFFF | Open Firmware 1.0.5 | 0 | identical: every Open Firmware address (FF80xxxx at run time) is the same |
| 360000-37FFFF | 68k emulator | 0 | identical (68060000 at run time) |
| 380000-3FFFFF | opcode table | 0 | identical (68080000) |

The timeline is the 7600's within 253 instructions (dingusppc, 604): Open
Firmware entered at instruction 1,436,986 (7600: 1,436,733), the NanoKernel
at 27,955,263 (27,955,010), Mac OS's 68k emulator in user mode from about 28.4
million.

## Where the addresses quoted in the docs move to

From the word-by-word alignment of the two ROMs' PowerPC code (branch
displacements masked); every one checked in the listings.

| 7600 ROM (28F2) | 7300 ROM (34F2) | what |
|---|---|---|
| FFF00100 | FFF00100 | the reset vector |
| FFF03000 | FFF03000 | the hardware start-up |
| FFF03094 | FFF030F4 | the data cache enabled |
| FFF03108 | FFF03168 | Hammerhead's CPU ID read through the data cache |
| FFF03ED4 | FFF04060 | the memory timing table |
| FFF0412C | FFF04308 | RAM sizing of one bank |
| FFF047C0 | FFF0499C | Cuda synchronisation |
| FFF04BC4, FFF04BCC | FFF04DA0, FFF04DA8 | the ten VIA reads after each Cuda byte |
| FFF04C94 | FFF04E70 | into the NanoKernel |
| FFF10000, FFF122B4, FFF12C50, FFF131B0, FFF15750 | the same | NanoKernel: entry, the `lwzux` of the update-form bug, the `rfi` with MSR[PM], the 604e SPR probes, the interrupt handler's Grand Central accesses |

| FFF3003C, FF80AAC8, FF80AB74, FF808D14, FF809C7C-FF80BB00, FF838BC0-FF838EA0 | the same | Open Firmware: entry, its Cuda routine, the flush word's `dcbst`, the old endless poll |
