## Rules

- SystemVerilog is fine, limited to what Verilator 5.020 and Quartus 17.0 both accept. Keep the RTL clean under Verilator `-Wall`. What Quartus 17 has refused so far: a second read expression on a memory (it becomes flip-flops), byte-enabled writes to a wide array (flip-flops again; `DSPPC604_cache_ram` is eight word RAMs with a write enable each, the shape it infers), a variable part-select of a two-dimensional array (flatten first), `genvar` declared inside the `for`, and a generate loop without `generate`/`endgenerate`. Verilator accepts all of these, so lint does not catch them; only a Quartus run does.
- Module and file names carry the CPU model: `DSPPC604_*`. Each later CPU model gets its own version.
- Real hardware outranks every emulator and the manual; of the emulators I trust dingusppc most. The 604 data is now two runs on the 7600 (`results_604_run2.csv`) and one on the 7300 (`results_604_7300_of_run1.csv`), identical where they overlap.

- Don't modify anything under `ppctest\`. `sys/` is the MiSTer framework and is never edited. Don't modify the dingusppc tree.
