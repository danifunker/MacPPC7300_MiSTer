## In flight when this was first written

1. **The RAM sizing: I chose 120 MB in the OSD and got 96.** FIXED in the RTL, build 26, on the board since: `PPCMac_machine.sv` "RAM: Hammerhead's banks" (one bank per power of two of the option, at the base the ROM writes, flat until a base is set); the 7300's ROM in the whole-machine bench at 120 MB packs the banks at 0, 64, 96 and 112 MB and the empty ones at 120 (a dev log of F80001C0-F80004F0's writes); the 16 MB lockstep stays identical. On the board: "About This Computer" in 7.6.1 at 120, 96, 48, 24, 6 MB; BootX with 120. The original notes follow. RAM was mapped flat from 0 (`PPCMac_machine.sv`: `is_ram = a[31:20] < ram_mb`; the ROM image sits in the SDRAM module's top 4 MB, so 124 MB is the most a 128 MB module allows). Hammerhead's bank base registers (1C0-4F0) are only stored and read back. The 7300's ROM sizes memory DIMM bank by DIMM bank (8-128 MB parts), so a flat 120 MB (not a power-of-two sum it can find bank by bank) may be found as 96 (64 + 32). Find how the ROM sizes RAM (dingusppc's `devices/memctrl/hammerhead.cpp`, `machines/machinetnt.cpp` RAM banks; the ROM's own code: a trace of Hammerhead register accesses on the board, or the ROM disassembly in `rom7300/`) and make the core present its RAM as banks the ROM accepts (e.g. 64 + 32 + 16 + 8 = 120 as four banks at the addresses the ROM programs). Also: with 120 MB, BootX did not start Linux (Mac OS stayed at "Starting Up..."), with 96 MB it did. Check "About This Computer" in Mac OS 7.6.1 for the size Mac OS sees at each setting.

## Rules

- SystemVerilog both Verilator 5.020 and Quartus 17.0 accept; Verilator `-Wall` clean (`make -s lint` in `verilator\`; the file list comes from `rtl/machine/PPCMac_machine.qip`). Quartus 17 refuses: a second read expression on a memory, two write statements on one RAM, byte-enabled writes to a wide array, a variable part-select of a two-dimensional array, `genvar` inside the `for`, a generate loop without `generate`, RAM style attributes, a three-input add or subtract as one expression, a RAM written from registers with a combinational read; an implicit `.name` port connection needs the same type. Declare before use.
- Machine modules are `PPCMac_*` under `rtl/machine/`. **`sys/` is never edited.**
- Real hardware outranks every emulator; dingusppc first among them; then MAME, Linux's and NetBSD's drivers, the chips' manuals; Apple's firmware and the OSes' own drivers (read off the board with the trace) are evidence too.
- Edit files with the editor tools (Edit, Write), not scripts, `sed` or heredocs. Generated files and copies are the exception.
- Commit at verified points with explicit paths (never `git add -A`), messages through a file (`git commit -F`), ending with the co-author line the harness gives. Never push or add a remote. Do not modify anything under `ppctest\` or the dingusppc tree. `Scratch\` is git-ignored. `PPCMac.qsf` only through a patch of your own lines (`git apply --cached`): Quartus rewrites its version line.
- Update `docs/PPCMac_stubs.md` in the same commit as any change to a stub. New code: comments short (the user's wish, for the Main above all).
- Never type passwords or other credentials into anything on the board (the user types them).
