## Milestone E: what the ROM asks for, and what dingusppc does

Where the RTL's path leaves dingusppc's: Mac OS's native SCSI Manager (the 34F2 ROM's `nitt` 43 resource, code at FFEBxxxx) reads MESH's ID register (F30180E0) at 82 million instructions here (86 million in dingusppc). dingusppc answers E2 (`mesh.h`: `TntMeshID`), the stub 0, and from there the SCSI Manager takes another path and never sets MESH up. In dingusppc's run (`rom7300/hw_access.txt`): MESH's bus status 0 polled from 29.1 million, the ID read, interrupt mask, source ID, sync parameters and the sequencer set up from 86.3 million, then from 230 million every target selected (sequence, destination ID and selection-timeout writes; the interrupt, exception and error registers read after each), to the end of the run; Curio (F3010000, a 53C94 with the Am53CF94's extra registers: the ROM reads its high transfer count register, F30100E0, as a chip probe at 86.8 million) set up at 86.8 million and every target selected from 355 million.

What it needs (rule 1: device modules behind the one device port, inside or beside `PPCMac_gc`):

- **MESH** at Grand Central's 18000 (registers 16 bytes apart, (offset >> 4) & F): transfer count 0/1, FIFO, sequence, bus status 0/1, FIFO count, exception, error, interrupt mask, interrupt, source ID, destination ID, sync parameters, MESH ID (E2), selection timeout. The sequencer commands (`mesh.h` `SeqCmd`: arbitrate, select, the phases, bus free, parity, reselect, reset MESH, flush FIFO), exception bits (selection timeout 1, phase mismatch 2, arbitration lost 4), interrupt bits (command done 1, exception 2, error 4), and dingusppc's bus controller sequence (`scsibusctrl.cpp`): bus free, arbitration (`scsi.h`: bus-free delay 800 ns plus settle 400, arbitration 2,400 ns), selection, and with no target a selection timeout after 250 ms (`SEL_TIME_OUT`; dingusppc ignores MESH's own selection-timeout register: check what the register's units are, from the code that writes it or from Linux's `mesh.c`, and say in the stubs list which you follow). The interrupt line, Grand Central source 0D, through `PPCMac_gc`'s events (rule 3). No DMA yet (channel 0A is S's).
- **Curio** at 10000 (`sc53c94.cpp`, `sc53c94.h`: read and write register maps differ; commands; selection with and without ATN; status, interrupt status, sequence step; the Am53CF94 extension registers the ROM probes): with no target, a selection ends in a timeout with a disconnect in the interrupt status and Grand Central source 0C.
- **Time**: the delays and the 250 ms by phase accumulation from the CPU's clock (rule 6), so the machine behaves the same at any `CPU_MHZ`.
- Keep everything else of the two controllers (data phases, DMA, reselection, targets) out until S, and write down in the stubs list exactly what is left out.

Proof (the plan's): the 7300's ROM in lockstep through Mac OS's probing of both buses (dingusppc's count: to 355 million instructions and past; at about 400,000 instructions a second, a billion take about 40 minutes: run long runs in the background with `--progress`, one WSL build at a time), its device traffic with the values matching dingusppc's apart from the differences already explained; the 7600's ROM still passing; the serial console still answering; then a bitstream on the board, where Mac OS keeps running through the probing (the readout's device writes growing, nothing stuck) and Open Firmware still answers on the modem port. ## Rules

- SystemVerilog, limited to what Verilator 5.020 and Quartus 17.0 both accept; Verilator `-Wall` clean (`make -s lint` in `verilator\`; it takes the machine's file list from `rtl/machine/PPCMac_machine.qip`, so a new file goes there). Quartus 17 refuses, silently or not: a second read expression on a memory, byte-enabled writes to a wide array, a variable part-select or bit-select of a two-dimensional array (take the word into a vector first), `genvar` inside the `for`, a generate loop without `generate`, every RAM style attribute, a three-input add or subtract as one expression (constants fold and are fine), a RAM written from registers with a combinational read. A comment line starting with "Verilator" is a Verilator metacomment.
- Machine modules are `PPCMac_*` under `rtl/machine/`. `sys/` is never edited; `rtl/pll*` is the template's PLL edited by hand (keep the instance names `sys_top.sdc` matches).
- Real hardware outranks every emulator; of the emulators dingusppc is trusted most; where dingusppc is high-level or does what real hardware cannot, MAME, then the chips' manuals.
- Edit files with the editor tools (Edit, Write), not scripts, `sed` or heredocs. Generated files (listings, logs, images made by the repository's own tools) are the exception.
- Commit at verified points with explicit paths (never `git add -A`), messages through a file (`git commit -F`), ending with the co-author line the harness gives. Never push or add a remote. Do not modify anything under `ppctest\` (another session's) or the dingusppc tree. Quartus rewrites a line of `PPCMac.qsf` (`LAST_QUARTUS_VERSION`); leave it out of commits (`git checkout -- PPCMac.qsf`).
